# Enabled Subsystem

## 端口

### 输入

### **In** — Subsystem 模块的信号输入 标量 | 向量 | 矩阵

Subsystem 模块的信号输入，指定为标量、向量或矩阵。在子系统中放置一个 Inport 模块会为 Subsystem 模块添加一个外部输入端口。端口标签与 Inport 模块的名称匹配。

使用 Inport 模块从局部环境接收信号。

**数据类型：** `half` | `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `Boolean` | `fixed point` | `enumerated` | `bus` | `image`

### **Enable** — Subsystem 模块的控制信号输入 标量 | 向量 | 矩阵

子系统中的 Enable 模块会为 Subsystem 模块添加一个外部输入端口，并使该模块成为 Enabled Subsystem 模块。

**数据类型：** `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `Boolean` | `fixed point`
### 输出

### **Out** — Subsystem 模块的信号输出 标量 | 向量 | 矩阵

Subsystem 模块的信号输出，以标量、向量或矩阵形式返回。在子系统中放置一个 Outport 模块会为 Subsystem 模块添加一个外部输出端口。端口标签与 Outport 模块的名称匹配。

使用 Outport 模块向局部环境发送信号。

**数据类型：** `half` | `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `Boolean` | `fixed point` | `enumerated` | `bus` | `image`

### 主要

### **Show port labels** — 端口标签的显示选项 `FromPortIcon`（默认）| `FromPortBlockName` | `SignalName` | `none`

选择如何在 Subsystem 模块图标上显示端口标签。

- `none` — 不显示端口标签。
- `FromPortIcon` — 如果对应端口图标显示信号名称，则在 Subsystem 模块上显示该信号名称。否则，显示端口模块名称，如果模块名称为默认名称，则显示端口号。
- `FromPortBlockName` — 在 Subsystem 模块上显示对应端口模块的名称。
- `SignalName` — 如果连接到端口的信号已命名，则在 Subsystem 模块上显示该信号名称。否则，显示对应端口模块的名称。

### **Read/Write permissions** — 对子系统内容的访问级别 `ReadWrite`（默认）| `ReadOnly` | `NoReadOrWrite`

控制用户对子系统内容的访问。

- `ReadWrite` — 允许打开和修改子系统内容。
- `ReadOnly` — 允许打开子系统但不允许修改。如果子系统位于模块库中，您可以创建并打开指向该子系统的链接，可以创建和修改子系统的本地副本，但不能更改权限或修改原始库实例的内容。
- `NoReadOrWrite` — 禁止打开或修改子系统。如果子系统位于库中，您可以在模型中创建指向该子系统的链接，但不能打开、修改、更改权限或创建子系统的本地副本。

如果您尝试查看 **Read/Write permissions** 参数设置为 `NoReadOrWrite` 的子系统内容，将不会收到任何响应。例如，双击此类子系统时，软件不会打开该子系统，也不会显示任何消息。

### 代码生成

Code Generation 选项卡上的参数需要 Simulink Coder™ 或 Embedded Coder® 许可证。

### **Function packaging** — 代码格式 `Auto` | `Inline` | `Nonreusable function` | `Reusable function`

选择要为原子（非虚拟）子系统生成的代码格式。

- `Auto` — 软件根据模型中存在的子系统类型和实例数量为您选择最佳格式。
- `Inline` — 软件无条件地内联子系统。
- `Nonreusable function` — 如果 **Filename options** 设置为 `Auto`，软件将单独的函数打包在模型文件中。如果 **File name options** 设置为 `Use subsystem name`、`Use function name` 或 `User specified` 并使用不同的文件名，则软件将单独的函数打包在单独的文件中。

  使用此设置的子系统生成的函数可能带有参数，具体取决于 Function interface 参数设置。您可以分别使用 Function name 和 File name (no extension) 参数来命名生成的函数和文件。这些函数不可重入。
- `Reusable function` — 软件生成带参数的函数，当模型包含子系统的多个实例时允许重用子系统代码。

  此选项还生成带参数的函数，允许在包含跨引用模型中子系统多个实例的模型引用层级的生成代码中重用子系统代码。在这种情况下，子系统必须位于库中。

有关详细信息，请参阅：

- 为单个子系统生成代码和可执行文件 (Simulink Coder)
- Generate Inlined Subsystem Code (Simulink Coder)
- 将子系统代码生成为单独的函数和文件 (Simulink Coder)
- 从跨模型共享的库子系统生成可重用代码 (Simulink Coder)

默认值取决于模块配置。例如，Subsystem 模块的默认值为 `Auto`。CodeReuseSubsystem 模块的默认值为 `Reusable function`。

#### 提示

- 当您希望将子系统的多个实例表示为一个可重用函数时，可以将每个实例指定为 `Auto` 或 `Reusable function`。最好只使用其中一种，因为同时使用两者会创建两个可重用函数，每种指定各一个。这些选择的结果仅在无法重用时才有所不同。选择 `Auto` 不允许控制子系统代码的函数名或文件名。
- `Reusable function` 和 `Auto` 选项都会尝试确定是否存在子系统的多个实例以及代码是否可以重用。每个选项行为的区别在于当无法重用时：

  - `Auto` 生成内联代码，或者如果情况不允许内联，则为每个子系统实例生成单独的函数。
  - `Reusable function` 为模型中的每个子系统实例生成一个带参数的单独函数。
- 如果您在生成的代码受源代码控制时选择 `Reusable function`，请将 **File name options** 设置为 `Use subsystem name`、`Use function name` 或 `User specified`。否则，每当您修改模型时，代码文件的名称都会更改，从而无法对文件进行源代码控制。
- 如果您选择 `Auto` 或 `Inline` 以外的选项，并且模型配置参数 **States**，代码生成器会生成单独的输出和更新方法。代码生成器不会考虑 **Combine output and update methods for code generation and simulation** 规范。

#### 依赖关系

- 此参数需要 Simulink Coder 许可证才能进行代码生成。
- 要启用此参数，请选择 **Treat as atomic unit**。

### **Function name options** — 如何命名生成的函数 `Auto` | `Use subsystem name` | `User specified`

选择软件为子系统生成的函数的命名方式。

如果您拥有 Embedded Coder 许可证，可以使用配置参数 **Code Generation** > **Identifiers** 窗格上的选项来控制函数名称。

- `Auto` — 使用默认命名约定 `model_subsystem()` 分配唯一的函数名称，其中 *`model`* 是模型名称，*`subsystem`* 是子系统名称，或者在代码被重用时为相同子系统的名称。

  如果您为 **Function packaging** 参数选择 `Reusable function`，并且模型引用层级包含可重用子系统的多个实例，则为了生成子系统的可重用代码，**Function name options** 必须设置为 `Auto`。
- `Use subsystem name` — 使用子系统名称作为函数名称。默认情况下，函数名称使用命名约定 `model_subsystem`。

  当子系统位于库模块中且子系统参数 Function packaging 设置为 `Reusable function` 时，如果您设置 `Use subsystem name` 选项，代码生成器将使用库模块的名称作为子系统函数名称和文件名。
- `User specified` — 启用 **Function name** 字段。输入任何合法的 C 或 C++ 函数名称，该名称必须唯一。

有关详细信息，请参阅 Generate Subsystem Code as Separate Function and Files (Simulink Coder)。

默认值取决于模块配置。例如，Subsystem 模块的默认值为 `Auto`。CodeReuseSubsystem 模块的默认值为 `Use subsystem name`。

#### 依赖关系

### **文件名选项** — 如何命名生成的文件 `Auto` | `Use subsystem name` | `Use function name` | `User specified`

选择软件如何为子系统生成的函数命名单独的文件。

- `Auto` — 根据子系统的配置以及模型中实例的数量，`Auto` 会产生不同的结果。

  - 如果代码生成器*不*为子系统生成单独的文件，则子系统代码将生成在从子系统父系统生成的代码模块中。如果子系统父系统是模型本身，则子系统代码将生成在 `model.c` 或 `model.cpp` 中。
  - 如果为 **Function packaging** 参数选择 `Reusable function`，并且生成的代码处于源代码控制之下，请考虑指定一个非 `Auto` 的 **File name options** 值。这可以防止生成的文件名因无关的模型修改而发生变化，这对于使用源代码控制来管理配置是有问题的。
  - 如果为 **Function packaging** 参数选择 `Reusable function`，并且模型引用层次结构包含可重用子系统的多个实例，为了为子系统生成可重用代码，**File name options** 必须设置为 `Auto`。
- `Use subsystem name` — 代码生成器生成一个单独的文件，使用子系统（或库模块）名称作为文件名。

  当 **File name options** 设置为 `Use subsystem name` 时，如果模型包含 Model 模块，或者正在为模型生成模型引用目标，则子系统文件名会被改编。在这些情况下，子系统的文件名由子系统名称加上模型名称前缀组成。
- `Use function name` — 代码生成器使用由 **Function name options** 指定的函数名作为文件名。
- `User specified` — 此选项启用 **File name (no extension)** 文本输入字段。代码生成器使用您输入的名称作为文件名。输入任意文件名，但不要包含 `.c` 或 `.cpp`（或任何其他）扩展名。此文件名不必唯一。

  虽然子系统源文件名不必唯一，但您必须避免使用会导致循环依赖的非唯一名称。例如，`sys_a.h` 包含 `sys_b.h`，`sys_b.h` 包含 `sys_c.h`，而 `sys_c.h` 包含 `sys_a.h`。

默认值取决于模块配置。例如，Subsystem 模块的默认值为 `Auto`。CodeReuseSubsystem 模块的默认值为 `Use function name`。

### **函数接口** — 如何使用生成函数的参数 `void_void`（默认）| `Allow arguments (Optimized)` | `Allow arguments (Match graphical interface)`

选择如何使用生成函数的参数。

- `void_void` — 生成不带参数的函数，并将数据作为全局变量传递。例如：

  ```
  void subsystem_function(void)
  ```
- `Allow arguments (Optimized)` — 生成使用参数而不是将数据作为全局变量传递的函数。此规范减少了全局 RAM。此选项可能会减小代码大小并提高执行速度，并使代码生成器能够应用额外的优化。例如：

  ```
  void subsystem_function(real_T rtu_In1, real_T rtu_In2,
                          real_T *rty_Out1)
  ```

  在某些情况下，当生成优化代码时，代码生成器可能不会生成带参数的函数。
- `Allow arguments (Match graphical interface)` — 生成使用与 Subsystem 图形模块接口匹配的参数的函数接口。生成的函数接口是可预测的且不会改变。可预测的接口对于调试和测试代码以及与外部应用程序集成非常有用。例如，如果模型有两个 Inport 模块和两个 Outport 模块，则生成的函数接口为：

  ```
  void subsystem_function(real_T rtu_In1, real_T rtu_In2,
                          real_T *rty_Out1, real_T *rty_Out2)
  ```

有关详细信息，请参阅：

- Reduce Global Variables in Nonreusable Subsystem Functions (Embedded Coder)
- 生成可预测的函数接口以匹配图形模块接口 (Embedded Coder)
- 为非虚拟子系统生成模块化函数代码 (Embedded Coder)

### **具有独立数据的函数** — 控制子系统的代码生成 `off`（默认）| `on`

生成子系统函数代码，其中原子子系统的内部数据与其父模型分离，并由子系统拥有。

- `off` — 不生成子系统函数代码，其中原子子系统的内部数据与其父模型分离并由子系统拥有。
- `on` — 生成子系统函数代码，其中原子子系统的内部数据与其父模型分离并由子系统拥有。子系统数据结构独立于父模型数据结构声明。具有独立数据的子系统拥有自己的模块 I/O 和 `DWork` 数据结构。因此，为子系统生成的代码更易于跟踪和测试。数据分离还倾向于减少整个模型中全局数据结构的最大大小，因为它们被拆分为多个数据结构。

有关如何为原子子系统生成模块化函数代码的详细信息，请参阅 Generate Modular Function Code for Nonvirtual Subsystems (Embedded Coder)。

有关如何将内存段应用于原子子系统的详细信息，请参阅 Override Default Memory Placement for Subsystem Functions and Data (Embedded Coder)。

#### 依赖关系

- 此参数需要 Embedded Coder 许可证和基于 ERT 的系统目标文件。
- 要启用此参数，请将 **Function packaging** 设置为 `Nonreusable function`。

### HDL 代码生成 使用 HDL Coder™ 为 FPGA 和 ASIC 设计生成 VHDL、Verilog 和 SystemVerilog 代码。

HDL Coder™ 提供影响 HDL 实现和综合逻辑的额外配置选项。

**最佳实践**

在面向 HDL 代码生成的模型中使用使能子系统时，建议考虑以下事项：

- 为使综合结果与 Simulink 结果匹配，Enable 端口必须由 FPGA 上的寄存逻辑（带同步时钟）驱动。
- 在使能子系统输出信号上放置单位延迟。这样做可以防止代码生成器在 HDL 代码中插入额外的旁路寄存器。
- 使能子系统可能通过以下方式影响综合结果：

  - 在某些情况下，系统时钟速度可能小幅下降。
  - 生成的代码使用更多资源，随使能子系统实例数量和每个子系统的输出端口数量而增加。

**HDL 架构**

| 架构 | 描述 |
| --- | --- |
| `Module`（默认） | 为子系统及子系统内的模块生成代码。 |
| `BlackBox` | 生成黑盒接口。生成的 HDL 代码仅包含子系统的输入/输出端口定义。因此，你可以在模型中使用子系统来生成与现有手写 HDL 代码的接口。子系统的黑盒接口生成类似于 Model 模块接口生成，但不包含时钟信号。 |
| `No HDL` | 从生成的代码中移除子系统。你可以在仿真中使用该子系统，但在 HDL 代码中将其视为“空操作”。 |

**目标规范**

此模块不能作为 DUT，因此 **Target Specification** 选项卡中的模块属性设置将被忽略。

**限制**

HDL Coder 支持对满足以下条件的使能子系统进行 HDL 代码生成：

- 使能子系统不是 DUT。
- 子系统不是*同时*被触发*和*使能。
- 使能信号是标量。
- 使能信号的输入数据类型为布尔型。
- 如果子系统的输出是总线，则输出端口的 **Initial condition** 必须为 0。
- 使能子系统的所有输入和输出（包括使能信号）以相同速率运行。
- Enable 模块的 **Show output port** 参数设置为 `Off`。
- Enable 模块的 **States when enabling** 参数设置为 `held`（即 Enable 模块在使能时不重置状态）。
- 使能子系统输出端口的 **Output when disabled** 参数设置为 `held`（即使能子系统在禁用时不重置输出值）。
- 如果 DUT 包含以下模块，则 `RAMArchitecture` 设置为 `WithClockEnable`：

  - Dual Port RAM
  - Simple Dual Port RAM
  - Single Port RAM
- 使能子系统不包含以下模块：

  - CIC Decimation
  - CIC Interpolation
  - FIR Decimation
  - FIR Interpolation
  - Downsample
  - Upsample
  - HDL FIFO
  - HDL Cosimulation 模块 (HDL Verifier™)
  - Rate Transition
  - NR Polar Encoder 和 NR Polar Decoder (Wireless HDL Toolbox™)

## 描述

由外部输入使能执行的子系统

Enabled Subsystem 模块是一个 Subsystem 模块，当外部信号具有正值时，它基于外部信号执行。当 Enable 端口的外部信号从负方向向正方向过零时，使能子系统执行。

Enabled Subsystem 模块通过将 Enable 模块放置在 Subsystem 模块内来配置。使能子系统的执行由 Enabled Subsystem 模块的 **Enable** 端口控制。

Enabled Subsystem 模块的内容。

使用 Enabled Subsystem 模块来建模：

- 子系统内模块执行的不连续性。例如，使用条件执行子系统的计数器中的计数器电路在子系统使能时递增，并在子系统禁用时保持其输出。
- 多个使能子系统，当这些子系统在 **Enable** 端口接收到正控制信号时执行。例如，请参阅使用使能子系统实现控制算法、控制模块状态和使能子系统的输出以及合并信号。
