## 参数

**指定信道的方式**
:   指定信道估计的方法。如果选择 `Input port`，模块会显示第二个输入端口，用于接收信道估计。如果选择 `Dialog`，可以在 **信道系数** 字段中将信道估计指定为 FIR 滤波器的系数向量。

**信道系数**
:   包含模块用于信道估计的 FIR 滤波器系数的向量。仅当将 **指定信道的方式** 设置为 `Dialog` 时，此字段才可见。

**信号星座**
:   用于指定调制星座的复数向量。

**回溯深度**
:   模块在 Viterbi 算法中用于构建每条回溯路径的网格分支数（亦即符号数）。

**工作模式**
:   Viterbi 解码器的工作模式。可选值为 `Continuous with reset option` 和 `Reset every frame`。

**输入包含前导码**
:   选中此项后，可以在 **预期前导码** 字段中设置前导码。仅当将 **工作模式** 设置为 `Reset every frame` 时，才会显示此选项。

**预期前导码**
:   表示前导码的整数向量，整数取值介于 0 和 M-1 之间，其中 M 为星座的大小。仅当将 **工作模式** 设置为 `Reset every frame`，然后选中 **输入包含前导码** 时，此字段才可见且处于启用状态。

**输入包含后导码**
:   选中此项后，可以在 **预期后导码** 字段中设置后导码。仅当将 **工作模式** 设置为 `Reset every frame` 时，才会显示此选项。

**预期后导码**
:   表示后导码的整数向量，整数取值介于 0 和 M-1 之间，其中 M 为星座的大小。仅当将 **工作模式** 设置为 `Reset every frame`，然后选中 **输入包含后导码** 时，此字段才可见且处于启用状态。

**每个输入符号的采样数**
:   每个星座点的输入采样数。

**启用复位输入端口**
:   选中此复选框后，模块将具有一个标签为 `Rst` 的第二个输入端口。向此端口提供非零输入值会使模块在处理输入数据之前将其内部存储器设置为初始状态。仅当将 **工作模式** 设置为 `Continuous with reset option` 时，才会显示此选项。

## 描述

使用 Viterbi 算法进行均衡

MLSE Equalizer 模块使用 Viterbi 算法，对通过色散信道的线性调制信号进行均衡。该模块处理输入帧，并利用建模为有限冲激响应 (FIR) 滤波器的信道估计，输出信号的最大似然序列估计 (MLSE)。

此模块支持 `single` 和 `double` 数据类型。

### 信道估计

信道估计采用列向量的形式，其中包含按幂次降序排列的 FIR 滤波器系数。此向量的长度为信道记忆长度，且必须是模块 **每个输入符号的采样数** 参数的整数倍。

要指定信道估计向量，请使用以下方法之一：

- 将 **指定信道的方式** 设置为 `Dialog`，并在 **信道系数** 字段中输入该向量。
- 将 **指定信道的方式** 设置为 `Input port`，模块会显示一个额外的输入端口，标签为 `Ch`，用于接收列向量输入信号。

### 信号星座

**信号星座** 参数指定调制信号的星座，该星座由模型中的调制器确定。**信号星座** 是由复数组成的向量，其中向量中的第 k 个复数表示调制器将整数 k-1 映射到的星座点。

**注意**

模型中调制器的星座点顺序必须与此模块的 **信号星座** 参数保持一致。

例如，要指定由以下映射给出的星座

0→+1+i1→−1+i2→−1−i3→+1−i

请将 **星座点** 设置为 `[1+i, -1+i, -1-i, 1-i]`。请注意，向量中数字的顺序指示调制器如何将整数映射到星座点集合。带标签的星座图如下所示。

### 前导码和后导码

如果数据附有前导码（前缀）或后导码（后缀），请相应地配置模块：

- 如果选择 **输入包含前导码**，则 **预期前导码** 参数指定您预期位于输入信号中数据之前的前导码。
- 如果选中 **输入包含后导码**，则 **预期后导码** 参数指定您预期位于输入信号中数据之后的后导码。

**预期前导码** 或 **预期后导码** 参数必须是取值介于 0 和 M-1 之间的整数向量，其中 M 为星座点的数量。向量中的整数值 k-1 对应于 **星座点** 向量中的第 k 项，因此也对应于调制器输入 k-1。

前导码或后导码必须已经分别包含在此模块输入信号的开头或末尾。如有必要，可以在 Simulink® 软件中使用 Matrix Concatenation 模块来串联向量。

要了解模块如何使用前导码和后导码，请参阅下面的 "Reset Every Frame" 工作模式。

### "Reset Every Frame" 工作模式

Viterbi 算法在连续帧之间进行转换的一种方式称为 `Reset every frame` 模式。可以使用 **工作模式** 参数选择此模式。

在 `Reset every frame` 模式下，模块独立解码每一帧数据，并在每帧结束时重置状态度量。回溯解码始终从状态度量最小的状态开始。

状态度量的初始化取决于是否指定了前导码和/或后导码：

- 如果未指定前导码，解码器会在每帧数据开始时将所有状态的度量初始化为 0。
- 如果指定了前导码，模块会使用它在每帧数据开始时初始化状态度量。更具体地说，模块对前导码进行解码，并为解码得到的状态分配度量值 0。如果前导码无法解码为唯一状态——即前导码长度小于信道记忆长度——解码器会为所有可由前导码表示的状态分配度量值 0。只要指定了前导码，回溯路径就会在前导码所表示的状态之一处结束。
- 如果未指定后导码，回溯路径从度量最小的状态开始。
- 如果指定了后导码，回溯路径从后导码所表示的状态开始。如果后导码无法解码为唯一状态，解码器会在后导码所表示的所有可能解码状态中确定最小的一个，并从该状态开始回溯解码。

  **注意**

  在 `Reset every frame` 模式下，MLSE Equalizer 模块的输入必须至少包含 T 个符号（不包括可选前导码），其中 T 为 **回溯深度** 参数。

### 连续工作模式

Viterbi 算法在连续帧之间进行转换的另一种方式称为 `Continuous with reset option` 模式。可以使用 **工作模式** 参数选择此模式。

在 `Continuous with reset option` 模式下，模块在仿真开始时将所有状态的度量初始化为 0。在每帧结束时，模块会保存内部状态度量，以便在下一帧中计算回溯路径。

如果选择 **启用复位输入端口**，模块会显示另一个标签为 `Rst` 的输入端口。在这种情况下，只要 `Rst` 端口的标量值为非零，模块就会重置状态度量。

### 解码延迟

MLSE Equalizer 模块在 `Continuous with reset option` 模式下引入的输出延迟等于 **回溯深度**，而在 `Reset every frame` 模式下没有延迟。
