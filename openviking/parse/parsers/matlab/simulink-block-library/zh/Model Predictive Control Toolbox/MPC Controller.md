# MPC Controller

## 端口

### 输入

#### 必需输入

### **mo** — 测量输出向量

测量输出，指定为向量信号。该模块使用被控对象测量输出来改进其状态估计。如果控制器使用默认状态估计，必须将被控对象测量输出连接到 **mo** 输入端口。如果控制器使用自定义状态估计，必须将被控对象估计状态连接到 **x[k|k]** 输入端口。

#### 依赖关系

要启用此端口，请清除 **Use custom state estimation instead of using the built-in Kalman filter** 参数。

### **x[k|k]** — 自定义状态估计向量

自定义状态估计，指定为向量信号。该模块使用连接的状态估计，而不是使用内置估计器来估计状态。如果控制器使用自定义状态估计，必须将当前状态估计连接到 **x[k|k]** 输入端口。如果控制器使用默认状态估计，必须将测量输出连接到 **mo** 输入端口。

即使噪声模型状态（如果有）不用于 MPC 优化，自定义状态向量也必须包含控制器的 `mpcstate` 对象中定义的所有状态，包括被控对象、扰动和噪声模型状态。

当替代估计技术被认为优于内置估计器时，或者当状态完全可测量时，请使用自定义状态估计。

#### 依赖关系

要启用此端口，请选择 **Use custom state estimation instead of using the built-in Kalman filter** 参数。

### **ref** — 模型输出参考值 行向量 | 矩阵

被控对象输出参考值，指定为行向量信号或矩阵信号。

若要在预测时域内使用相同的参考值，请将 **ref** 连接到具有 *Ny* 个元素的行向量信号，其中 *Ny* 是输出变量数。每个元素指定一个输出变量的参考值。

若要在预测时域内（预览）从时间 *k*+1 到时间 *k*+*p* 改变参考值，请将 **ref** 连接到具有 *Ny* 列且最多 *p* 行的矩阵信号。这里，*k* 是当前时间，*p* 是预测时域。每一行包含一个预测时域步的参考值。如果指定的行数少于 *p*，则最终参考值用于预测时域的剩余步。

#### 附加输入

### **md** — 输入 行向量 | 矩阵

如果控制器预测模型具有测量扰动，则必须启用此端口，并将行向量或矩阵信号连接到该端口。

若要在预测时域内使用相同的测量扰动值，请将 **md** 连接到具有 *Nmd* 个元素的行向量信号，其中 *Nmd* 是操纵变量数。每个元素指定一个测量扰动的值。

若要在预测时域内（预览）从时间 *k* 到时间 *k*+*p* 改变扰动，请将 **md** 连接到具有 *Nmd* 列且最多 *p*+1 行的矩阵信号。这里，*k* 是当前时间，*p* 是预测时域。每一行包含一个预测时域步的扰动。如果指定的行数少于 *p*+1，则最终扰动用于预测时域的剩余步。

#### 依赖关系

要启用此端口，请选择 **Measured disturbances** 参数。

### **ext.mv** — 上一控制区间用于被控对象的控制信号向量

上一控制区间用于被控对象的控制信号，指定为长度为 *Nmv* 的向量信号，其中 *Nmv* 是操纵变量数。在以下情况下，使用此输入端口可提高状态估计精度：

- 您知道控制器并非始终控制被控对象。
- 施加到被控对象的实际 MV 信号可能不同于控制器生成的值，例如在控制信号饱和时。

控制器状态估计假设 MV 是分段常数。因此，在时间 *tk*，**ext.mv** 值必须包含时间 *tk–1* 与 *tk* 之间的有效 MV。例如，如果 MV 在该区间内实际变化，您可以提供在时间 *tk* 评估的时间平均值。

**注意**

- 将 **ext.mv** 连接到上一控制区间实际施加到被控对象的 MV 信号。通常，这些 MV 信号是控制器生成的值，但并非总是如此。例如，如果控制器离线并运行在跟踪模式（即控制器输出未驱动被控对象），则将实际控制信号馈送到 **ext.mv** 有助于在控制器重新联机时实现无扰动切换。
- 当控制器正在驱动被控对象时，插入 Memory 模块或 Unit Delay 模块，以反馈上一控制区间施加到被控对象的 MV 信号。这还可避免从 **ext.mv** 输入端口到 **mv** 输出端口的前馈直通，从而防止 Simulink 模型中出现代数环。

有关使用外部操纵变量输入端口实现无扰动切换的示例，请参阅 Switch Controller Online and Offline with Bumpless Transfer。

#### 依赖关系

要启用此端口，请选择 **External manipulated variable** 参数。

### **switch** — 启用或禁用优化标量

要关闭控制器优化计算，请将 **switch** 连接到非零信号。

当不需要控制器输出时（例如系统手动运行或另一控制器接管时），禁用优化计算可减少计算量。但是，控制器会继续按常规方式更新其内部状态估计。因此，只要 **switch** 信号返回零，它就可以恢复优化计算。当控制器优化关闭时，该模块会将当前 **ext.mv** 信号传递到控制器输出。如果未启用 **ext.mv** 输入端口，则控制器输出保持在禁用优化时的值。

有关使用外部操纵变量输入端口实现无扰动切换的示例，请参阅 Switch Controller Online and Offline with Bumpless Transfer。

#### 依赖关系

要启用此端口，请选择 **Use external signal to enable or disable optimization** 参数。

### **mv.target** — 操纵变量目标向量

要指定操纵变量目标，请启用此输入端口，并连接向量信号。要使给定操纵变量跟踪其指定目标值，还必须为该操纵变量指定非零调优权重。

运行时提供的 **mv.target** 值应用于整个预测时域。

#### 依赖关系

要启用此端口，请选择 **Targets for manipulated variables** 参数。

#### 在线约束

### **ymin** — 最小输出变量约束 向量 | 矩阵

要指定运行时最小输出变量约束，请启用此输入端口。如果此端口被禁用，该模块将使用其 `mpc` 控制器对象的 `OutputVariables.Min` 属性中指定的下界。如果控制器对象中未为某个输出变量指定下界，则在运行时该模块会忽略相应连接的信号。

若要在预测时域内从时间 *k*+1 到时间 *k*+*p* 更改边界，请将 **ymin** 连接到具有 *Ny* 列且最多 *p* 行的矩阵信号。这里，*Ny* 是被控对象输出数，*k* 是当前时间，*p* 是预测时域。每一行包含一个预测时域步的边界。如果指定的行数少于 *p*，则最终行中的边界适用于预测时域的剩余部分。如果只有一个输出变量，并且连接了不超过 *p* 个元素的向量信号，则这些元素将用于整个预测时域。

**ymin** 信号的第 `i` 列对应于第 `i` 个被控对象输出，并在运行时替换 `mpc` 对象的 `OutputVariables(i).Max` 属性。替换行为取决于两个变量的维度。

**`mpc` 对象中的标量 `OutputVariables(i).Min`（对第 `i` 个被控对象输出应用且用于所有预测步的常数边界）**

| **ymin** 维度 | 替换行为 |
| --- | --- |
| 标量 **ymin**（单个输出，常数边界） | **ymin** 替换 `OutputVariables(i).Min` 中定义的常数边界。 |
| 列向量 **ymin**（单个输出，时变边界） | **ymin** 将 `OutputVariables(i).Min` 中定义的常数边界替换为时变边界。 |
| 行向量 **ymin**（多个输出，常数边界） | **ymin** 的第 `i` 个元素替换 `OutputVariables(i).Min` 中定义的常数边界。 |
| 矩阵 **ymin**（多个输出，时变边界） | **ymin** 的第 `i` 列将 `OutputVariables(i).Min` 中定义的常数边界替换为时变边界。 |

**`mpc` 对象中的向量 `OutputVariables(i).Min`（第 `i` 个被控对象输出的时变边界，在不同预测步具有不同值）**

| **ymin** 维度 | 替换行为 |
| --- | --- |
| 标量 **ymin**（单个输出，常数边界） | **ymin** 替换 `OutputVariables.Min` 中的第一个有限项，`OutputVariables.Min` 中的其余项以相同位移量上移或下移，以保留原始 `OutputVariables.Min` 向量定义的曲线。 |
| 列向量 **ymin**（单个输出，时变边界） | **ymin** 替换 `OutputVariables(i).Min` 中定义的时变边界，并丢弃原始边界曲线。 |
| 行向量 **ymin**（多个输出，常数边界） | **ymin** 的第 `i` 个元素替换 `OutputVariables(i).Min` 中的第一个有限项，`OutputVariables(i).Min` 中的其余项以相同位移量上移或下移，以保留原始 `OutputVariables(i).Min` 向量定义的曲线。 |
| 矩阵 **ymin**（多个输出，时变边界）。 | **ymin** 的第 `i` 列替换 `OutputVariables(i).Min` 中定义的时变边界，并丢弃原始边界曲线。 |

#### 依赖关系

要启用此端口，请选择 **Lower OV limits** 参数。

### **umin** — 最小操纵变量约束 vector | matrix

要指定运行时最小操纵变量约束，请启用此输入端口。如果禁用此端口，模块使用其 `mpc` 控制器对象的 `ManipulatedVariables.Min` 属性中指定的下界。如果控制器对象中未为某个操纵变量指定下界，则运行时模块忽略相应的已连接信号。

要更改从时刻 *k* 到时刻 *k*+*p*-1 的预测时域上的边界，请将 **umin** 连接到具有 *Nmv* 列和最多 *p* 行的矩阵信号。其中，*Nmv* 是操纵变量数，*k* 是当前时间，*p* 是预测时域。每一行包含一个预测时域步长的边界。如果指定的行数少于 *p*，则最后一行中的边界应用于预测时域的剩余部分。如果只有一个操纵变量，并且连接了条目数不超过 *p* 的向量信号，则这些条目用于整个预测时域。

### **E** — 操纵变量约束矩阵 matrix

操纵变量约束矩阵，指定为 *Nc*×*Nmv* 矩阵信号，其中 *Nc* 是混合输入/输出约束的数量，*Nmv* 是操纵变量的数量。

如果在 `mpc` 对象中定义 `E`，则必须将信号连接到 **E** 输入端口。否则，连接大小正确的零矩阵。

### 输出

#### 必需输出

### **mv** — 最优操纵变量控制动作列向量

最优操纵变量控制动作，输出为长度为 *Nmv* 的列向量信号，其中 *Nmv* 是操纵变量的数量。

如果求解器收敛到局部最优解（**qp.status** 为正），则 **mv** 包含最优解。

如果求解器失败（**qp.status** 为负），则 **mv** 保持在其最近一次成功求解的值；也就是说，控制器输出冻结。

如果求解器达到最大迭代次数而未找到最优解
（**qp.status** 为零），并且控制器的
`Optimization.UseSuboptimalSolution` 属性
为：

- `true`，则 **mv** 包含次优解
- `false`，则 **mv** 然后 **mv** 保持在其最近一次成功求解的值

#### 附加输出

### **cost** — 目标函数代价非负标量

目标函数代价，输出为非负标量信号。该代价量化控制器实现其目标的程度。代价值使用缩放后的 MPC 代价函数计算，其中每一项都是无偏置且无量纲的。

仅当 **qp.status** 输出为非负时，代价值才有意义。

#### 依赖关系

要启用此端口，请选择 **Optimal cost** 参数。

### **qp.status** — 优化状态整数

优化状态，输出为整数信号。

如果控制器针对给定控制区间求解 QP 问题，则 **qp.status** 输出返回计算中使用的 QP 求解器迭代次数。此值是有限的正整数，并与计算所需时间成正比。因此，较大的值意味着该时间区间内模块执行相对较慢。

QP 求解器可能由于以下原因无法找到最优解：

- **qp.status** = `0` — QP 求解器无法在 `mpc` 对象中指定的最大迭代次数内找到解。在这种情况下，如果控制器的 `Optimizer.UseSuboptimalSolution` 属性为 `false`，则模块将其 **mv** 输出保持在最近一次成功求解的值。否则，它使用最后一次求解器迭代期间找到的次优解。
- **qp.status** = `-1` — QP 求解器检测到不可行的 QP 问题。有关大而持续的扰动驱动输出变量超出其指定边界的示例，请参阅监控优化状态以检测控制器故障。在这种情况下，模块将其 **mv** 输出保持在最近一次成功求解的值。
- **qp.status** = `-2` — QP 求解器在求解严重病态的 QP 问题时遇到数值困难。在这种情况下，模块将其 **mv** 输出保持在最近一次成功求解的值。

在实时应用中，可以使用 **qp.status** 设置报警或采取其他特殊操作。

#### 依赖关系

要启用此端口，请选择 **Optimization status** 参数。

### **est.state** — 估计的控制器状态向量

每个控制时刻的估计控制器状态，返回为向量信号。估计状态包括被控对象、扰动和噪声模型状态。如果使用自定义状态估计，则此输出信号的值与 **x[k|k]** 输入信号相同。

#### 依赖关系

要启用此端口，请选择 **Estimated controller states**
参数。

#### 最优序列

### **mv.seq** — 最优操纵变量序列矩阵

最优操纵变量序列，返回为具有 *p*+1 行和 *Nmv* 列的矩阵信号，其中 *p* 是预测时域，*Nmv* 是操纵变量的数量。

**mv.seq** 的前 *p* 行包含从当前时刻 *k* 到时刻 *k*+*p*-1 计算出的最优操纵变量值。**mv.seq** 的第一行包含当前操纵变量值（输出 **mv**）。由于控制器不计算时刻 *k*+*p* 的最优控制动作，因此 **mv.seq** 的最后两行相同。

#### 依赖关系

要启用此端口，请选择 **Optimal control sequence** 参数。

### **x.seq** — 最优预测模型状态序列矩阵

最优预测模型状态序列，返回为具有 *p*+1 行和 *Nx* 列的矩阵信号，其中 *p* 是预测时域，*Nx* 是状态数量。

**x.seq** 的第一行包含当前估计状态值，这些值要么来自内置状态估计器，要么来自自定义状态估计模块输入 **x[k|k]**。**x.seq** 的接下来 *p* 行包含从时刻 *k*+1 到时刻 *k*+*p* 计算出的最优状态值。

#### 依赖关系

要启用此端口，请选择 **Optimal state sequence** 参数。

### **y.seq** — 最优输出变量序列矩阵

最优输出变量序列，返回为具有 *p*+1 行和 *Ny* 列的矩阵信号，其中 *p* 是预测时域，*Ny* 是输出变量的数量。

**y.seq** 的前 *p* 行包含从当前时刻 *k* 到时刻 *k*+*p*-1 计算出的最优输出值。**y.seq** 的第一行基于当前估计状态和当前测量扰动（输入 **md** 的第一行）计算。由于控制器不计算时刻 *k*+*p* 的最优输出值，因此 **y.seq** 的最后两行相同。

#### 依赖关系

要启用此端口，请选择 **Optimal output sequence** 参数。

### **继承采样时间** — 从父子系统继承模块采样时间 `off`（默认）| `on`

选择此参数可将父子系统的采样时间作为模块采样时间继承。这样可以在 Function-Call Subsystem (Simulink) 或 Triggered Subsystem (Simulink) 模块内有条件地执行此模块。有关示例，请参阅在 Function-Call 和 Triggered 子系统内使用 MPC Controller 模块。

**注意**

必须按控制器的采样率执行 Function-Call Subsystem 或 Triggered Subsystem 模块。否则，可能由于以下两个原因看到意外结果。

- MV 速率向量的第一个元素（即操纵变量当前值与上一个值之差）通常会进行加权和约束，并假定上一个 MV 值发生在过去，且发生在 MPC 对象中指定的采样时间；当模块以不同采样率执行时，此假设不再成立。
- 内置 Kalman 估计器使用 MPC 对象中指定的采样时间向 MPC 优化问题提供当前状态的估计；因此，当模块以不同采样时间执行时，估计状态不再正确。

如果清除此参数（默认），模块的采样时间将从控制器对象继承。

要查看模块的采样时间，请在 Simulink 模型窗口的 **Debug** 选项卡上，在 **Information Overlays** 下，选择 **colors** 或 **Text**。有关详细信息，请参阅查看采样时间信息 (Simulink)。

### R2018b：MPC Simulink 模块 `mv.seq` 输出端口信号维度已更改

MPC Controller 模块的 `mv.seq` 输出端口的信号维度已更改。以前，此信号是 *p* 乘 *Nmv* 矩阵，其中 *p* 是预测时域，*Nmv* 是操纵变量数量。现在，`mv.seq` 是 (*p*+1) 乘 *Nmv* 矩阵，其中第 *p*+1 行重复第 *p* 行。

## 描述

仿真模型预测控制器

MPC Controller 模块接收当前测量输出信号（`mo`）、参考信号（`ref`）以及可选的测量扰动信号（`md`）。该模块通过使用默认 KWIK 求解器或自定义 QP 求解器求解二次规划问题，计算最优操纵变量（`mv`）。有关详细信息，请参阅线性 MPC 的 QP 求解器。

要在仿真和代码生成中使用该模块，必须指定一个 `mpc` 对象，该对象定义模型预测控制器。此控制器必须已经针对其所控制的被控对象设计完成。

由于 MPC Controller 模块使用 MATLAB Function 模块，因此每次更改 MPC 对象和模块时都需要编译。此外，由于 MATLAB® 不允许编译代码位于任何 MATLAB 产品文件夹中，因此使用 MPC 模块时，必须使用非 MATLAB 文件夹来处理 Simulink® 模型。
