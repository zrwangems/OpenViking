# AXI4-Stream to Software

## 端口

### 输入

### **wrData** — 写入器数据总线信号 标量 | 向量 | 矩阵

此信号包含要写入内存的数据。

**数据类型：** `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `Boolean` | `fixed point`

### **wrCtrlIn** — 写入器输入控制信号 总线

此端口表示从数据生产者到处理器的协议。AXI4-Stream to Software 模块在使用 **wrData** 时检查此信号。控制总线上的信号类型为 `StreamM2SBusObj`。要创建此控制总线，请使用 SoC Bus Creator 模块。有关总线类型的详细信息，请参阅外部内存通道协议。

**数据类型：** `StreamM2SBusObj`

### **done** — 已完成读取的通知消息 标量

此消息端口从连接的 Stream Read 模块接收通知。该通知指示读事务已完成。有关消息的详细信息，请参阅消息。

**数据类型：** `Boolean`

### 输出

### **event** — 任务读取事件信号 标量

此端口发送任务事件信号，该信号触发 Task Manager 模块执行关联的事件驱动读取。

**数据类型：** `rteEvent`

### **msg** — 输出到软件的数据信号 标量 | 向量 | 矩阵

此信号包含从内存读取的数据，并作为消息发送到连接的 Stream Read 模块。有关消息的详细信息，请参阅消息。

**数据类型：** `SoCData`

### **wrCtrlOut** — 到数据生产者的写入器控制信号 总线

此总线表示从内存通道到数据生产者的协议总线。总线上的信号类型为 `StreamS2MBusObj`。要从总线中分离信号，请使用 SoC Bus Selector 模块。

**数据类型：** `StreamS2MBusObj`

## 参数

### **内存仿真** — 设置仿真时序精度 `Burst accurate` (默认) | `Protocol accurate` | `Behavioral`

内存仿真提供三个级别的时序分辨率。请选择以下选项之一：

- **Burst accurate** — 仿真内存争用和高分辨率时序。
- **Protocol accurate** — 仿真 AXI4 协议握手序列和低分辨率时序。
- **Behavioral** — 仅仿真数据事务，不仿真时序。

  当此参数设置为 **Behavioral** 模式时，`TLAST` 信号的值将被忽略。

### 主要

### **内存选择** — 选择内存区域 `PS memory` (默认) | `PL memory`

在处理子系统 (PS) 或可编程逻辑 (PL) 内存之间进行选择。

- 如果所选板卡仅支持 PL memory，则默认值为 `PL memory`。
- 如果所选板卡仅支持 PS memory 或仅支持 PL memory，则此参数为只读。
- 如果所选板卡不是受支持的 SoC 板卡，则此参数不可见。

### **区域大小 (bytes)** — 已分配内存区域的大小，以 bytes 为单位 只读：计算得出

此参数为只读。

区域大小（以 bytes 为单位）的值。此值按缓冲区数量乘以缓冲区大小计算。缓冲区大小定义为数据大小乘以软件帧大小。通过在 **信号属性** 选项卡上设置 **数据类型** 和 **维度** 参数来定义此值。

**示例：** 软件帧大小为 1024 uint32 时，定义的缓冲区为 4096 Bytes。如果缓冲区数量设置为 2，则区域大小为 8192 bytes。

### **缓冲区数量** — 区域中的缓冲区数量 `8` (默认) | 整数

定义内存中的缓冲区数量。

内存访问具有环形缓冲区模式。只要缓冲区可用，写入器就可以持续写入。当缓冲区完成时，它变为可供读取器使用。写入器和读取器以循环模式遍历缓冲区。只要写入器和读取器保持相近的速率，缓冲就会防止阻塞。

读取器和写入器之间的速率差异会减慢较快的设备。例如，较慢的读取器会导致写入器耗尽缓冲区并阻塞写入器，从而有效地将写入器减慢到读取器的速率。同样，较慢的写入器会导致读取器耗尽缓冲区并阻塞读取器，从而有效地将读取器减慢到写入器的速率。

**缓冲区数量** 参数必须为 3 到 64 的整数。

### **突发长度** — 内存事务的突发长度 `256` (默认) | 标量

此连接在内存总线上的突发长度，以标量数据为单位。标量单位是打包的数据类型。为写入器和读取器对通道的访问指定突发大小。

通道数据始终使用突发事务传输到内存模型。对于 AXI4 配置，算法逻辑负责通过协议信号定义突发。

**突发长度** 参数确定到内存的突发大小，**wrData** 信号定义接口上每次传输的大小。

### **FIFO 深度 (突发数量)** — 数据 FIFO 的深度 `8` (默认) | 标量

以突发为单位指定数据 FIFO 的深度。当写入器没有可写入的缓冲区时，FIFO 可以吸收数据，直到有缓冲区可用。此值是 FIFO 在丢弃数据之前可以缓冲的最大突发数量。

#### 依赖关系

要启用此参数，请在 **内存仿真** 下选择 **Burst accurate**。

### **FIFO 几乎满深度 (突发数量)** — 置位背压时的 FIFO 深度 `6` (默认) | 标量

指定一个数字，用于从通道向数据源置位背压信号。为避免丢弃数据，请设置较高的水位，使数据生产者有足够时间对背压做出反应。此数字必须小于 FIFO 深度。

#### 依赖关系

要启用此参数，请在 **内存仿真** 下选择 **Burst accurate**。

### **时钟频率 (MHz)** — 管理器数据通路的互连频率 `100` (默认)

以 MHz 为单位指定管理器数据通路的频率。

#### 依赖关系

要启用此参数，请在 **内存仿真** 下选择 **Burst accurate**。

### **数据位宽 (bits)** — 管理器数据通路的数据位宽 `64` (默认) | 标量

以 bits 为单位指定到互连控制器的管理器数据通路的数据位宽。

#### 依赖关系

要启用此参数，请在 **内存仿真** 下选择 **Burst accurate**。

### 信号属性

#### 流数据信号

### **维度** — 输入数据信号的维度 1 (默认) | 标量 | 数组

**wrData** 可以是多维数组。将数组的维度指定为整数。

**示例：** 1 — 一个标量样本。

**示例：** [10 1] — 十个标量的向量。

**示例：** [1080 1920 3] — 一个 1080p 帧。该帧包含 1080 行，每行 1920 像素，每个像素由三个值表示（分别对应红色、绿色和蓝色）。

### **数据类型** — 写入器数据的数据类型 `uint32` (默认) | `double` | `single` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint64` | `Boolean` | `fixed point`

指定 **wrData** 端口的数据类型。如需帮助，请单击 **...** 按钮并选择 **数据类型助手**。

### **采样时间** — 采样时间间隔 1 (默认) | 正标量 | 向量

以秒为单位指定时间间隔，以定义模块更新的频率。

当不希望输出具有时间偏移时，请将 **采样时间** 参数指定为标量。要为输出添加时间偏移，请将 **采样时间** 参数指定为 `1`×`2` 向量，其中第一个元素是采样周期，第二个元素是偏移。有关 Simulink® 中采样时间的详细信息，请参阅指定采样时间。

### **启用样本打包（最后一个信号维度作为通道）** — 在信号的最后一个维度上打包数据 `off` (默认) | `on`

选择此参数以启用沿信号最后一个维度的数据打包。AXI4-Stream to Software 模块沿信号的最后一个维度打包数据。例如，如果通道数据类型为 `uint32`，维度为 `[1024 4]`。如果选择此样本打包参数，则内存通道生成 1024 个 128 位的读或写事务。如果清除此样本打包参数，则内存通道生成 4096 个每个 32 位的事务。

下图显示数据类型为 `fixdt10[4x3]` 的信号的数据对齐方式。当数据被打包时，三个 10 位字串联并扩展 2 位，组成一个 32 位字。当数据未打包时，每个 10 位字扩展为一个 16 位字。

顶行显示打包数据按 10、10、10 和 2 的样本对齐，以构成 32 位。底行显示未打包数据按 10 和 6 的样本对齐，以构成 16 位。

下图显示数据类型为 `uint8[8x3]` 的信号的数据对齐方式。当数据被打包时，三个 8 位字串联并扩展 8 位，组成一个 32 位字。当数据未打包时，每个 8 位字表示为一个 8 位样本。

顶行显示打包数据按 8、8、8 和 8 的样本对齐，以构成 32 位。底行显示未打包数据按 8 位的样本对齐。

展平后的信号的总宽度不得超过 512 位。

## 描述

将 AXI4 数据从 FPGA 流式传输到软件

AXI4-Stream to Software 模块通过外部内存对硬件逻辑与软件任务之间的连接进行建模。写入器使用 MathWorks® 简化 AXI 流协议将数据放入通道，读取器（处理器）从 DMA 驱动接口获取数据。该模块对该连接的数据通路和软件栈进行建模，包括 FIFO、DMA 引擎、互连和外部内存、中断、DMA 驱动的内核缓冲区管理，以及到软件任务的数据传输。

此模块等效于一个 Memory Channel 模块（其 **通道类型** 参数设置为 `AXI4-Stream to Software via DMA`）连接到一个 Memory Controller 模块。

由于内存控制器是设计中隐式的，因此可以实例化多个内存模块，它们通过一个内存控制器连接到同一内存单元。有效模块包括：

- AXI4 Random Access Memory
- AXI4-Stream to Software
- Software to AXI4-Stream
- AXI4 Video Frame Buffer
- Memory Traffic Generator

一个模型中的管理器接口最大数量为 16。

连接到 Memory Controller 模块的 Memory Channel 模块，由 AXI4-Stream to Software 模块替代。

有关 MathWorks 简化 AXI 流协议的详细信息，请参阅 AXI4-Stream 接口。
