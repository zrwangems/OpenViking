# Software to AXI4-Stream

## 端口

### 输入

### **msg** — 来自软件的输入数据信号 标量 | 向量 | 矩阵

此信号包含从处理器发送到算法的数据。

**数据类型：** `SoCData`

### **rdCtrlIn** — 读取器输入控制信号总线

此端口接受来自数据消费者模块的控制总线，表示消费者模块已准备好接受读取数据。**rdCtrlIn** 端口是从数据消费者到 Software to AXI4-Stream 模块的背压信号。要创建此控制总线，请使用 SoC Bus Creator 模块。

**数据类型：** `StreamS2MBusObj`

### 输出

### **rdData** — 到数据消费者的输出数据信号 标量 | 向量 | 矩阵

此信号包含通过内存从处理器读取的数据。

**数据类型：** `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `Boolean` | `fixed point`

### **rdCtrlOut** — 到数据消费者的读取器控制信号总线

此信号表示从内存通道到数据消费者的协议总线。将此信号连接到数据消费者。要从控制总线中分离该信号，请使用 SoC Bus Selector 模块。

**数据类型：** `StreamM2SBusObj`

### **event** — 任务写事件信号 标量

此端口发送任务事件信号，触发 Task Manager 模块执行关联的事件驱动写入。

**数据类型：** `rteEvent`

### **done** — 内存中已释放缓冲区的通知 标量

此消息端口向连接的 Stream Write 模块发送通知。此通知表示读取事务已完成，并且内存中的缓冲区可用于写入。

**数据类型：** `Boolean`

## 参数

### **内存仿真** — 设置仿真时序精度 `Burst accurate`（默认）| `Protocol accurate` | `Behavioral`

内存仿真提供三个级别的时序分辨率。选择以下选项之一：

- **Burst accurate** — 模拟内存争用和高分辨率时序。
- **Protocol accurate** — 模拟 AXI4 协议握手顺序和低分辨率时序。
- **Behavioral** — 仅模拟数据事务且不模拟时序。

  当此参数设置为 **Behavioral** 模式时，`TLAST` 信号的值将被忽略。

### 主要

### **内存选择** — 在内存区域之间选择 `PS memory`（默认）| `PL memory`

在处理子系统 (PS) 或编程逻辑 (PL) 内存之间选择。

- 如果所选板卡仅支持 PL memory，则默认值为 `PL memory`。
- 如果所选板卡仅支持 PS memory 或仅支持 PL memory，则此参数为只读。
- 如果所选板卡不是受支持的 SoC 板卡，则此参数不可见。

### **区域大小 (bytes)** — 分配的内存区域大小，以字节为单位 只读：计算得出

此参数为只读。

区域大小以 bytes 为单位。此值计算为缓冲区数量乘以缓冲区大小。缓冲区大小定义为数据大小乘以软件帧大小。通过设置 **信号属性** 选项卡上的 **数据类型** 和 **维度** 参数来定义此值。

**示例：** 1024 个 uint32 的软件帧大小定义 4096 Bytes 的缓冲区。如果缓冲区数量设置为 2，则区域大小为 8192 bytes。

### **缓冲区数量** — 区域中的缓冲区数量 8（默认）| 整数

定义内存中的缓冲区数量。

内存访问采用环形缓冲区模式。只要有可用缓冲区，写入器就可以持续写入。当一个缓冲区完成时，它就可供读取器使用。写入器和读取器以循环模式遍历缓冲区。只要写入器和读取器保持相似的速率，缓冲就可防止阻塞。

读取器和写入器之间的速率差异会减慢较快的设备。例如，慢速读取器会导致写入器耗尽缓冲区并阻塞写入器，从而有效地将写入器减慢到读取器的速率。同样，慢速写入器会导致读取器耗尽缓冲区并阻塞读取器，从而有效地将读取器减慢到写入器的速率。

**缓冲区数量** 参数必须是 3 到 64 之间的整数。

### **突发长度** — 内存事务的突发长度 256（默认）| 标量

内存总线上此连接的突发长度，以标量数据为单位。标量单位是打包数据类型。为写入器和读取器对通道的访问指定突发大小。

通道数据始终使用突发事务传输到内存模型。对于 AXI4 配置，算法逻辑负责通过协议信号定义突发。

**突发长度** 参数确定到内存的突发大小，而 **rdData** 信号定义接口上每次传输的大小。

### **FIFO 深度（突发数）** — 数据 FIFO 的深度 `8`（默认）| 标量

指定数据 FIFO 的深度，以突发数为单位。当写入器没有可写入的缓冲区时，FIFO 可以吸收数据，直到有缓冲区可用。此值是 FIFO 在丢弃数据之前可以缓冲的最大突发数。

#### 依赖关系

要启用此参数，请在 **内存仿真** 下选择 **Burst accurate**。

### **FIFO 几乎满深度（突发数）** — 断言背压时的 FIFO 深度 `6`（默认）| 标量

指定一个数字，该数字会断言从通道到数据源的背压信号。为避免丢弃数据，请设置一个高水位标记，使数据生产者有足够时间对背压做出反应。此数字必须小于 FIFO 深度。

#### 依赖关系

要启用此参数，请在 **内存仿真** 下选择 **Burst accurate**。

### **时钟频率 (MHz)** — 管理器数据通路的互连频率 `100`（默认）

指定管理器数据通路的频率，以 MHz 为单位。

#### 依赖关系

要启用此参数，请在 **内存仿真** 下选择 **Burst accurate**。

### **数据宽度 (bits)** — 管理器数据通路的数据宽度 `64`（默认）| 标量

指定到互连控制器的管理器数据通路的数据宽度，以 bits 为单位。

#### 依赖关系

要启用此参数，请在 **内存仿真** 下选择 **Burst accurate**。

### 信号属性

#### 软件数据信号

### **维度** — 软件数据的维度 `1024`（默认）| 标量

将软件数据（写入器）的维度指定为整数。

默认值为 `1024`。

### **数据类型** — 软件数据的数据类型 uint32（默认）| uint16 | uint64 | `fixdt(1,16,0)`

指定软件数据（写入器）的数据类型。如需帮助，请点击 **...** 按钮并选择 **Data Type Assistant**。默认情况下，此值设置为从源信号继承数据类型。

#### 流数据信号

### **维度** — 输出数据信号的维度 1（默认）| 标量 | 数组

**rdData** 可以是多维数组。将数组的维度指定为整数。

**示例：** 1 — 标量样本。

**示例：** [10 1] — 十个标量组成的向量。

**示例：** [1080 1920 3] — 一个 1080p 帧。该帧包含 1080 行，每行 1920 个像素，每个像素由三个值表示（分别对应红、绿、蓝）。

### **数据类型** — 读取器数据的数据类型 `Inherit: Same as input`（默认）| `double` | `single` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `Boolean` | `fixed point`

指定 **rdData** 端口的数据类型。如需帮助，请点击 **...** 按钮并选择 **Data Type Assistant**。默认情况下，此值设置为从源信号继承数据类型。

### **采样时间** — 采样时间间隔 1（默认）| 正标量 | 向量

指定以秒为单位的时间间隔，以定义模块更新的频率。

当您不希望输出具有时间偏移时，请将 **采样时间** 参数指定为标量。要向输出添加时间偏移，请将 **采样时间** 参数指定为 `1`-by-`2` 向量，其中第一个元素是采样周期，第二个元素是偏移量。有关 Simulink® 中采样时间的详细信息，请参阅 Specify Sample Time。

### **启用样本打包（最后信号维度作为通道）** — 在信号的最后维度上打包数据 `off`（默认）| `on`

选择此参数可启用在信号最后维度上的数据打包。AXI4-Stream to Software 模块沿信号最后维度打包数据。例如，如果通道数据类型为 `uint32`，维度为 `[1024 4]`。如果选择此样本打包参数，则内存通道会生成 1024 个 128 bits 的读或写事务。如果清除此样本打包参数，则内存通道会生成 4096 个事务，每个事务为 32 bits。

下图显示了数据类型为 `fixdt10[4x3]` 的信号的数据对齐方式。当数据被打包时，三个 10-bit 字被串联并扩展 2 bits，形成 32-bit 字。当数据未打包时，每个 10-bit 字被扩展为 16-bit 字。

顶行显示打包数据按 10、10、10 和 2 的样本对齐，以形成 32 bits。底行显示未打包数据按 10 和 6 的样本对齐，以形成 16 bits。

下图显示了数据类型为 `uint8[8x3]` 的信号的数据对齐方式。当数据被打包时，三个 8-bit 字被串联并扩展 8 bits，形成 32-bit 字。当数据未打包时，每个 8-bit 字表示为 8-bit 样本。

顶行显示打包数据按 8、8、8 和 8 的样本对齐，以形成 32 bits。底行显示未打包数据按 8 bits 的样本对齐。

展平信号的总宽度不得超过 512 bits。

## 描述

从软件向 FPGA 流式传输 AXI4 数据

Software to AXI4-Stream 模块通过外部内存对硬件逻辑和软件任务之间的连接进行建模。写入器（处理器）使用 MathWorks® 简化 AXI 流协议通过 DMA 驱动程序将数据流式传输到通道中。该模块对该连接的数据通路和软件栈进行建模，包括 FIFO、DMA 引擎、互连和外部内存、中断、DMA 驱动程序的内核缓冲区管理，以及来自软件任务的数据传输。

此模块等效于将 **通道类型** 参数设置为 `Software to AXI4-Stream via DMA` 的 Memory Channel 模块连接到 Memory Controller 模块。

由于内存控制器对设计而言是隐式的，因此您可以实例化多个内存模块，这些模块通过一个内存控制器连接到同一个内存单元。有效的模块包括：

- AXI4 Random Access
  Memory
- AXI4-Stream to
  Software
- Software to
  AXI4-Stream
- AXI4 Video Frame
  Buffer
- Memory Traffic
  Generator

模型中管理器接口的最大数量为 16。

连接到 Memory Controller 模块的 Memory Channel 模块，已由 Software to AXI4-Stream 模块替代

有关 MathWorks 简化 AXI 流协议的详细信息，请参阅 AXI4-Stream Interface。
