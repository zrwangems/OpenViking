# Rate Transition

## 端口

### 输入

### **Port\_1** — 输入信号 标量 | 向量 | 矩阵 | N-D 数组

转换到新采样率的输入信号，指定为标量、向量、矩阵或 N-D 数组。要了解使您能够在数据完整性和确定性传输与更快的响应或更低的内存需求之间进行权衡的模块参数，请参阅转换处理行为。

**数据类型：** `single` | `double` | `half` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `Boolean` | `fixed point` | `enumerated` | `bus`

### 输出

### **Port\_1** — 输出信号 标量 | 向量 | 矩阵 | N-D 数组

转换为您指定的采样率的输入信号。默认配置确保安全且确定性的数据传输。要了解使您能够在数据完整性和确定性传输与更快的响应或更低的内存需求之间进行权衡的模块参数，请参阅转换处理行为。

**数据类型：** `single` | `double` | `half` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `Boolean` | `fixed point` | `enumerated` | `bus`

## 参数

### **确保数据传输期间的数据完整性** — 确保数据完整性 `on` (默认) | `off`

选择此参数会生成确保模块传输数据时数据完整性的代码。如果选择此参数并且传输是非确定性的（参见 **确保确定性数据传输**），则根据输入速率和输出速率的优先级，生成的代码使用适当的算法，通过单个或多个缓冲区来在数据传输期间保护数据完整性。

否则，Rate Transition 模块会被简化，或者通过使用复制操作来执行数据传输，从而生成代码。此未受保护模式消耗更少内存。但是，复制操作是可中断的，这可能导致数据传输期间数据完整性丢失。如果希望生成的代码以最大响应能力（即非确定性地）运行并保持数据完整性，请选择此参数。有关更多信息，请参阅生成的代码中的控制数据传输行为 (Simulink Coder)。

### **确保确定性数据传输（最大延迟）** — 确保确定性数据传输 `on` (默认) | `off`

选择此参数会生成以较慢模块的采样率传输数据（即确定性地）的代码。如果不选择此参数，则当源模块有新数据可用且接收模块准备好接收数据时，会发生数据传输。这样可避免传输延迟，从而确保系统以最大响应能力运行。但是，传输可能不可预测地发生，这在某些应用中是不希望的。有关更多信息，请参阅生成的代码中的控制数据传输行为 (Simulink Coder)。

### **初始条件** — 初始条件 `0` (默认) | 标量 | 向量 | 矩阵 | N-D 数组

此参数仅适用于慢至快转换。它指定转换开始时 Rate Transition 模块的初始输出，此时由于没有来自慢模块的输入信号而没有输出信号。Simulink® 不允许此模块的初始输出为 `Inf` 或 `NaN`。您指定的值必须是标量，或与输入信号具有相同维度。

### **输出端口采样时间选项** — 用于指定输出端口采样时间的模式 `Specify` (默认) | `Inherit` | `Multiple of input port sample time`

指定用于设置输出端口采样时间的模式。

- `Specify` — 使用 **输出端口采样时间** 参数指定模块将其输入速率转换到的输出速率。
- `Inherit` — 模块从输出端口所连接的模块继承输出速率。
- `Multiple of input port sample time` — 使用 **采样时间倍数 (>0)** 参数将模块输出速率指定为其输入速率的倍数。

如果选择 `Inherit`，并且连接到输出端口的模块也继承采样时间，则应用模型中最快的采样时间。

### **输出端口采样时间** — 输出速率 `-1` (默认) | 标量 | 向量

输入一个值，指定模块将其输入速率转换到的输出速率。默认值 (`-1`) 指定 Rate Transition 模块从输出端口所连接的模块继承输出速率。有关如何指定输出速率的信息，请参阅指定采样时间。

#### 依赖项

要启用此参数，请将 **输出端口采样时间选项** 设为 `Specify`。

### **采样时间倍数 (>0)** — 采样时间倍数 `1` (默认) | 正标量

## 扩展功能

### C/C++ 代码生成 使用 Simulink® Coder™ 生成 C 和 C++ 代码。

- 在某些条件下，例如对于多维信号，生成的代码依赖 `memcpy` 或 `memset` 函数（`string.h`）。
- 不要在触发子系统层级内使用 Rate Transition 模块。
- 并发程序生成的代码是平台特定的，并假定部署平台和开发平台相同。

### HDL 代码生成 使用 HDL Coder™ 为 FPGA 和 ASIC 设计生成 VHDL、Verilog 和 SystemVerilog 代码。

HDL Coder™ 提供影响 HDL 实现和综合逻辑的配置选项。

**最佳实践**

- 当 Rate Transition 模块以快输入速率和慢输出速率运行时，最好在 Rate Transition 模块之后接一个单位延迟。这样做可防止代码生成器在 HDL 代码中插入额外的旁路寄存器。另请参阅用于 HDL 代码生成的多速率模型要求 (HDL Coder)。
- 要在不引入单位延迟的情况下对输入信号进行上采样，请按如下方式配置 Rate Transition 模块参数：

  - 清除 **确保数据传输期间的数据完整性**。

    清除此参数会隐藏 **确保确定性数据传输（最大延迟）** 参数。
  - 将模块的输出端口采样时间配置为输入端口采样时间的整数倍。为 **采样时间倍数** 指定小数值 `1/n`，其中 `n` 是整数。如果 **采样时间倍数** 使用值 `1/n`，则可以为模块参数 **输出端口采样时间选项** 选择任意值。

  **注意**

  对输入信号进行下采样时，保留 **确保数据传输期间的数据完整性** 和 **确保确定性数据传输（最大延迟）** 参数为选中状态。此模式会在 HDL 代码中生成额外的旁路寄存器。

  另请参阅 Rate Change 和 Constant 模块的用法 (HDL Coder)。

**限制**

- 对于模块输入或输出端口，采样率不能为 `0` 或 `Inf`。

**HDL 架构**

此模块有一个默认 HDL 架构。

**HDL 模块属性**

|  |  |
| --- | --- |
| **ConstrainedOutputPipeline** | 通过在设计内移动现有延迟，在输出处放置的寄存器数量。分布式流水线不会重新分配这些寄存器。默认值为 `0`。有关更多详细信息，请参阅 ConstrainedOutputPipeline (HDL Coder)。 |
| **InputPipeline** | 在生成的代码中插入的输入流水线级数。分布式流水线和受约束输出流水线可以移动这些寄存器。默认值为 `0`。有关更多详细信息，请参阅 InputPipeline (HDL Coder)。 |

| **AsyncRTAsWire** | 将异步速率转换映射为 Wire。当 **输出端口采样时间** 具有非整数值时，它被视为异步速率。启用 **AsyncRTAsWire** 选项以在 Rate Transition 模块存在此类异步速率时生成 wire。**依赖项：** 仅当 **确保数据传输期间的数据完整性** 和 **确保确定性数据传输** 参数设为 `off` 时，此选项可用。将异步速率转换用作 wire 时，将 **Clock inputs** 选项设为 `Multiple`。 |

将异步速率转换映射为 wire 时，您可能会看到 Simulink 与代码生成结果之间存在数值不匹配。

## 描述

处理以不同速率运行的模块之间的数据传输

Rate Transition 模块将数据从一个以某个速率运行的模块输出传输到以不同速率运行的模块输入。使用模块参数在数据完整性和确定性传输与更快的响应或更低的内存需求之间进行权衡。要了解数据完整性和确定性数据传输，请参阅 Data Transfer Considerations (Simulink Coder)。

### 转换处理行为

| 行为 | 参数设置 | 说明 |
| --- | --- | --- |
| - 数据完整性 - 确定性数据传输 - 最大延迟 | 选择：  - **确保数据传输期间的数据完整性** - **确保确定性数据传输** | - 生成的代码传输数据，使得信号的数据字节（包括宽信号的元素）来自同一时间步。 - 数据从一个速率传输到另一个速率的相对采样时间（延迟）相同。 - 代码生成器仅生成 ANSI® C 代码。 - 不需要目标特定的临界区保护。 |
| - 数据完整性 - 非确定性数据传输 - 最小延迟 - 更高的内存需求 | 选择：  - **确保数据传输期间的数据完整性**  清除：  - **确保确定性数据传输** | - 生成的代码传输数据，使得信号的数据字节（包括宽信号的元素）来自同一时间步。 - 数据传输的相对采样时间（延迟）可能因每次数据传输而异。读取和写入数据的代码运行频率高于选择 **确保数据传输期间的数据完整性** 和 **确保确定性数据传输** 时的情况。在最坏情况下，延迟等同于选择 **确保数据传输期间的数据完整性** 和 **确保确定性数据传输** 时的延迟，但延迟可能更小，这对某些应用很重要。 - 支持与异步速率之间的数据传输。 - 代码生成器仅生成 ANSI C 代码。 - 不需要目标特定的临界区保护。 |
| - 潜在的数据完整性丢失 - 非确定性数据传输 - 最小延迟 - 更低的内存需求 | 清除：  - **确保数据传输期间的数据完整性** - **确保确定性数据传输** | - 代码生成器不会为 Rate Transition 模块生成代码。 - 适用于保证标量数据类型原子访问且数据的相对时间值不重要的应用。 - 不会引入延迟。 |

Rate Transition 模块的行为取决于：

- 模块所连接端口的采样时间（参见同步采样时间的影响和异步采样时间的影响）
- 源和目标采样时间对应任务的优先级（参见采样时间属性）
- 模型指定的是固定步长还是可变步长求解器（参见比较求解器）
- 模型配置参数 **Device vendor** 和 **Device type** 的设置（参见设备配置的影响）

### 设备配置的影响

如果模型配置参数 **设备供应商** 和 **设备类型** 的设置指定了支持原子数据加载和存储操作的硬件，则当目标硬件支持对所传输信号的数据类型进行原子加载和存储操作时，代码生成器会优化生成的速率转换代码。代码生成器利用硬件的加载和存储能力，将异步任务之间的双缓冲代码替换为执行单次内存复制的代码。
